# Stackstone Networking Report System — Full Architecture

## What this does

You speak to someone at a networking event. You optionally record the conversation
(with their consent). You enter their name, email, and company website. Within
~60 seconds they receive an email with a link to a bespoke, branded AI opportunity
report — hosted on your website, generated from real research into their company.

---

## Components

### Website (Replit) — does all the heavy lifting

- POST /api/intake — receives contact data, runs the full pipeline
- GET /report/[uuid] — serves the branded report page
- POST /api/transcribe — transcribes audio recording via Whisper

Pipeline per submission:
1. Validate all fields server-side
2. Companies House lookup (confirms company is real, gets SIC code, size)
3. Deep website fetch (/about, /services, /team) + brand colour extraction
4. Claude generates structured report JSON
5. Store report with UUID
6. Call Pi's /send-report to send the email
7. Return report URL to browser immediately

### Pi / L1 — email sending only

- POST /send-report — scoped endpoint, called only by the website
- Sends one email via MS Graph from your mailbox
- Rate limited to 30/day by default
- NEVER touches L1's TOTP queue or general email flow
- Health check at GET /health

### Browser (your phone) — intake form only

- intake-app/index.html — open in your phone browser, no install
- Captures name, email, website
- Optional audio recording with MediaRecorder API, transcribed server-side
- Live validation — submit button stays disabled until all fields pass
- History of sent contacts stored in localStorage

## Setup

### 1. Replit

Hand Replit the full prompt in docs/replit-build-prompt.md.

Add these to Replit Secrets:
  ANTHROPIC_API_KEY         existing
  OPENAI_API_KEY            for Whisper transcription
  COMPANIES_HOUSE_API_KEY   from developer.company-information.service.gov.uk
  PI_ENDPOINT_URL           https://your-tunnel.trycloudflare.com/send-report
  INTAKE_SITE_SECRET        choose a strong secret, same value on Pi

### 2. Pi — new send-report server

  cd pi-endpoint
  npm install
  node send-report-server.js

Add to your Pi .env:
  INTAKE_SITE_SECRET        same value as in Replit
  MS_GRAPH_TOKEN            valid Graph token with Mail.Send scope
  SENDER_EMAIL              tom@stackstoneconsulting.co.uk
  SENDER_NAME               Tom Dean
  REPORT_PORT               5051
  MAX_PER_DAY               30
  TELEGRAM_CHAT_ID          1744801946
  TELEGRAM_BOT_TOKEN        your bot token

### 3. Cloudflare tunnel — recommended: named tunnel for stability

One-time setup gives you a stable subdomain rather than a random URL each restart:

  cloudflared tunnel create stackstone-reports
  cloudflared tunnel route dns stackstone-reports reports.stackstoneconsulting.co.uk

Then in ~/.cloudflared/config.yml:
  tunnel: <tunnel-uuid>
  credentials-file: /home/pi/.cloudflared/<tunnel-uuid>.json
  ingress:
    - hostname: reports.stackstoneconsulting.co.uk
      service: http://localhost:5051
    - service: http_status:404

  cloudflared tunnel run stackstone-reports

Set PI_ENDPOINT_URL in Replit to: https://reports.stackstoneconsulting.co.uk/send-report

### 4. Browser intake app

Open intake-app/index.html in your phone browser.
Tap "Configure endpoint" and enter your Replit app URL.
The form talks to Replit directly — not to the Pi.

## What the contact receives

Email from tom@stackstoneconsulting.co.uk:
  Clean branded covering note with a single CTA button.
  Link does not expire.

Report page at /report/[uuid]:
  Stackstone branded header + amber rule
  Companies House data strip (number, SIC, incorporation date)
  Executive summary addressing them by name
  Sector AI context — specific to their industry
  Primary opportunity — named, with time-to-value and ROI indicator
  Three 90-day quick wins — actionable cards
  Honest caveats
  "Based on our conversation..." block (only if transcript captured)
  PDF download button (clean A4 print stylesheet)
  CTA to book a session

## What makes this different to the current briefing pack

Current pack:
  Website + company name only
  Single Claude call, minimal context
  Generic sector content
  No company verification
  No brand personalisation
  L1 TOTP required for email

New system:
  Website + live conversation transcript
  Companies House + deep website crawl + transcript fed to Claude
  Cites specific things from their website
  Companies House confirms company is real and active
  Extracts their brand colour if found confidently, else Stackstone only
  Scoped Pi endpoint, no TOTP, completely separate flow
