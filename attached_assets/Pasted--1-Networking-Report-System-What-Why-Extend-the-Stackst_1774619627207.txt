#1 - Networking Report System
What & Why
Extend the Stackstone website with a networking event report system. When Tom meets someone at an event, he captures their name, email, and company website (optionally recording the conversation). The system runs a deep research pipeline — Companies House lookup, multi-page website crawl with brand colour extraction, optional Whisper transcription — then generates a bespoke AI opportunity report via Claude and serves it as a branded page at /report/[uuid]. Report delivery details are exposed via the existing integration API so the Pi (OpenClaw) can poll for new reports and send the emails via MS Graph — the same pattern used for leads and packs today.

This is a significant upgrade over the existing briefing pack: it adds Companies House verification, conversation transcript integration, brand colour personalisation, and structured email delivery data for the Pi.

Done looks like
POST /api/intake accepts contact details + optional transcript, validates inputs, runs the full pipeline (Companies House → website crawl → Claude report generation → store), and returns the report URL
GET /report/[uuid] renders a branded, responsive HTML report page with: company data strip (Companies House), executive summary, sector context, primary opportunity card, three quick-win cards, caveats, transcript insights (if present), PDF download button (print stylesheet), and CTA footer
POST /api/transcribe accepts audio upload (webm/mp4, max 25MB) and returns a transcript via OpenAI Whisper
GET /api/integration/reports returns unsent/new reports with the email payload the Pi needs (to, reportUrl, companyName, firstName) — authenticated with INTEGRATION_API_KEY, same as existing integration endpoints
PATCH /api/integration/reports/:uuid/sent lets the Pi mark a report as email-sent after delivery
The intake form is served at /intake as a mobile-first page with name/email/website fields, optional audio recording via MediaRecorder API, live validation, and submission history in localStorage
New database table stores reports with UUID, contact info, transcript flag, full report JSON, brand colour, emailSent status, and timestamps
Environment secrets are requested: OPENAI_API_KEY, COMPANIES_HOUSE_API_KEY
Report pages work as clean A4 PDFs via window.print() with a print stylesheet
Out of scope
Pi/OpenClaw email sending (built separately in the OpenClaw fork)
Authentication or admin UI for reports (UUID is the access control)
Cloudflare tunnel setup (no longer needed — Pi polls the integration API)
Modifying the existing briefing pack system
Tasks
Database schema and storage — Add a networking_reports table (uuid, contact fields, hasTranscript, report JSON, brandColour, emailSent boolean, status, timestamps) and extend the storage interface with CRUD methods.

Companies House service — Create a service that searches the Companies House API by company name (derived from domain), extracts registered name, company number, SIC codes, status, and incorporation date.

Enhanced website scraper — Extend the existing scraper to also fetch /team and /our-team pages, extract brand colours from CSS (fetch primary stylesheet, find dominant hex colours excluding near-black/near-white), and return structured research data including colour.

Whisper transcription endpoint — Add POST /api/transcribe that accepts multipart audio upload (max 25MB), sends to OpenAI Whisper API (whisper-1 model), and returns the transcript text.

Intake pipeline and API route — Build POST /api/intake implementing the pipeline: validate → Companies House → website crawl → Claude report generation (structured JSON with the specified schema) → store report. Return 202 with reportUrl and uuid.

Integration API for report delivery — Add GET /api/integration/reports (returns reports where emailSent is false, with the email payload shape: to, reportUrl, companyName, firstName) and PATCH /api/integration/reports/:uuid/sent (marks a report as sent). Use the existing INTEGRATION_API_KEY auth and rate limiting from the integration module.

Report viewer page — Build the /report/[uuid] client page: branded header with Stackstone logo + contact name + date, Companies House data strip, executive summary, sector context, primary opportunity card with brand colour accent, three quick-win cards, caveats list, conditional transcript insights block, PDF download button (print stylesheet), and CTA mailto footer.

Intake form page — Serve the mobile-first intake form at /intake with the provided design (charcoal/slate/amber theme), name/email/website fields, optional audio recording section using MediaRecorder API with transcription, live validation bar, submission status overlay, and localStorage history.

Environment secrets — Request OPENAI_API_KEY and COMPANIES_HOUSE_API_KEY from the user and configure them.
