# SKILL: Weekly Review — Friday System Review

## When to use
Every Friday. Triggered by cron or by Tom asking "weekly review" or "Friday review".

## Purpose
Improve the system, not just reflect on the week.
The output should be concrete changes, not a vague summary.

## Process

### Step 1 — Review active work
- Read TASKS.md — what was completed, what is stale, what should be dropped
- Read BACKLOG.md — reprioritise, drop duplicates, flag anything urgent
- Read PLAN.md — what happened vs what was planned

### Step 2 — Review learnings
- Read MEMORY.md — anything outdated or wrong?
- Read SOUL_PENDING.md — are there proposed changes ready to present to Tom?
- Note: NEVER auto-promote SOUL_PENDING.md to SOUL. Present proposals to Tom only.

### Step 3 — Review system health
- Read SYSTEM_HEALTH.md — any recurring failures?
- Check cron log freshness against reference/CRONS.md
- Flag anything that has been failing for more than a week

### Step 4 — Review integrations
- GARMIN_ARCHIVE.md — any health trends worth noting?
- STACKSTONE_ENQUIRIES.md — leads received this week, any patterns?
- STACKSTONE_REPORTS.md — reports sent this week

### Step 5 — Propose improvements
Based on the above, identify:
- 1-3 concrete BACKLOG items to add or elevate
- Any MEMORY.md updates needed
- Any skill updates needed
- Any SYSTEM_MAP.md updates needed

### Step 6 — Write changes
- Update TASKS.md (remove done, update stale)
- Add new items to BACKLOG.md
- Update MEMORY.md with any new durable learnings
- Update SYSTEM_MAP.md if anything changed

### Step 7 — Report to Tom
Post a concise weekly review summary:
- What was done
- What is being carried forward
- What is being proposed
- Any system improvements made
